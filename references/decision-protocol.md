# 근거 기반 실험 선택과 큐 연결

모든 신규 후보에 적용한다. 검증 가능한 근거·가정·결정 요약을 작성한다. 내부 사고 과정의 전문이나 장황한 독백은 요구하지 않는다. 수치가 없는 칸은 `미확인`으로 남기고, 이를 확인할 관측을 지정한다.

## 1. 관측과 해석을 분리한다

- **사실:** P id·큐 ID·계약·seed·평가 범위·출처와 함께 관측값을 적는다. 전후 차이는 같은 계약·지원 격자·단위에서만 계산한다.
- **가설:** 관측을 설명하는 메커니즘을 적는다. 성능 악화만으로 누출·과적합·정보 부재·물리 모델 실패를 확정하지 않는다.
- **미확인:** 코드·artifact를 직접 못 봤다면 확인되지 않은 연결을 표시하고 워커가 확인할 파일·식·로그를 지정한다. 실행 가능한 계약이나 데이터 가용성이 미확인인 후보는 큐에 쓰지 않는다.
- 비교 기준을 분리한다: 현재 계약의 기준선/확정 챔피언, 계보 직전 단계, 계보 최고 단계. 직전 단계 대비 회복을 챔피언 개선으로 부르지 않는다. REPLAY만 있으면 `초기 기준선(REP 확정 아님)`으로 표시한다.

## 2. 정보가 끊기는 지점을 찾는다

`입력 → 정렬·전처리 → 학습 타깃 → 목적함수 → 추론 출력 → 물리 변환 → 그룹 집계 → W` 중 관측과 맞지 않는 지점을 찾는다. 다단계·잔차 모델 또는 큰 악화가 나온 계보는 다음 대응표를 작성한다.

| 점검 | 학습·검증과 최종 추론에서 확인할 것 |
|---|---|
| 타깃과 합성식 | 학습 타깃, 모델이 출력하는 양, 최종 발전량 복원식, 단위·정규화·역변환 |
| 기준 모델 | fold별 모델과 전체 기간 refit 모델, OOF와 in-sample 예측, 잔차 기준의 일치 여부 |
| 목적함수와 갱신 | 실제 최종 출력에 걸린 손실, freeze/detach, gradient가 도달하는 파라미터 |
| 관측 지원 | 라벨 결측 mask, 사이트 가동 기간, 그룹 합의 관측 지원; 결측 라벨을 0으로 대체하지 않음 |
| 인과·재현 | 발행 시각, fit 컷오프, artifact 버전, fresh inference의 poison check, seed별 비교 |

이 점검은 진단과 구현 검증이다. smoke 점수나 내부 fold 결과로 전체 3-seed 평가를 생략하는 게이트로 쓰지 않는다. 계약 위반·잘못된 구현의 점수는 과학적 반증으로 사용하지 않는다.

## 3. 경쟁 설명과 구분 관측을 짝짓는다

주가설 H_A와 가장 가까운 경쟁 설명 H_B를 적는다. 각 설명에서 예상되는 **중간 관측의 방향**과 그 차이를 적는다. W 개선만으로 둘을 구분할 수 없으면 컷오프 이전 chronological 검증의 진단을 추가하거나 주장 범위를 줄인다.

예: 잔차 모델이 `r = y − f_fold(x)`로 학습하고 추론은 `f_full(x) + r_hat(x)`라면 다음을 검토한다.
- H_A: 기준 모델 교체로 잔차 분포가 달라졌다. 컷오프 이전 검증에서 fold/refit 기준의 차이와 합성 출력 오차가 함께 달라지는지 측정한다.
- H_B: 표현이나 최적화가 부족하다. 기준을 맞춰도 합성 출력의 학습·검증 오차가 남는지 측정한다.
- 가능한 개입: 동일 구조에서 최종 합성 출력에 손실을 걸고 공동 학습한다. 입력·분할·모델 크기·후처리는 유지한다. 공동 학습도 최적화를 바꾸므로 성공만으로 H_A가 증명되지는 않는다. 진단이 두 설명을 분리하지 못하면 `판별 유보`다.
- 이 예는 후보 생성 방식이다. 공동 학습을 모든 계보의 정답으로 고정하거나 물리 잠재변수의 식별 가능성을 주장하지 않는다.

## 4. 다음 행동을 바꾸는 최소 개입을 고른다

가장 가까운 대안 후보와 함께 아래 표를 채운다. 문헌은 메커니즘의 근거로 사용하고, 현재 병목은 내부 관측으로 확인한다.

| 후보 | 근거 ID·관측 | H_A / H_B | 구분할 관측 | 바꾸는 것·유지할 것 | 기존 큐와 차이 | 결과별 다음 행동 | 결정·이유 |
|---|---|---|---|---|---|---|---|
| … | … | … | … | … | … | … | 추가 / 기존 큐가 담당 / 보류 / 기각 |

- 순서는 계약·데이터·비중복·예산 충족 → 필수 REPLAY/REPLICATE → 결과가 준비된 ARCH 다음 단계 → 병목 직접성과 판별력 → 비용으로 정한다. 근거 없는 기대 W나 임의 점수 합으로 순위를 만들지 않는다.
- INCREMENT·PIVOT·ARCH-STEP은 선택한 한 개입과 나머지 불변 조건을 적는다. ARCH s1은 전체 구조를 명세한다. COMBINE은 재현된 재료의 결합 효과를 검정한다.
- 결과를 미리 세 갈래로 적는다: **지지**(예상 중간 관측과 full W 결과), **반증/약화**(유효한 평가에서 예상과 반대), **판별 유보**(진단 누락·가설 공통 예측·기술 실패·불충분 표본). 각 갈래에서 다음에 유지·변경·종료할 구체적 대상을 지정한다.
- 한 구현의 실패는 그 구현·입력·계약에서 검정한 주장만 약화시킨다. 모델 계열 전체나 정보원 전체를 닫으려면 그 범위를 직접 검정한 근거가 있어야 한다.
- REPLAY/REPLICATE는 기존 전용 양식을 따른다. 목적은 각각 계약 기준선 확보와 개선 재현이다. 새 개입이나 억지 경쟁 가설을 추가하지 않는다.

## 5. 큐가 이미 맡고 있는 질문을 확인한다

연구 탭의 실행 상태와 큐를 함께 읽고 `대기 / 실행 중 / 완료 / 기술 실패 / 종료`를 구분한다. 이름·날짜 대신 **질문·개입·base·계약·입력·계보/단계·재현 대상**을 비교한다.

- H1/H5의 PIVOT 조치와 H8의 ARCH 조치는 현재 조건을 충족하는 대기·실행 중 행이 맡고 있으면 충족이다. 해당 ID와 맡은 질문을 보고한다. 금지 유형·불법 입력을 쓰는 기존 행은 충족으로 세지 않는다.
- 활성 ARCH에 대기·실행 중 단계가 있으면 그 계보의 다음 단계를 새로 쓰지 않는다. 완료된 단계의 결과와 진단을 보고 다음 개입을 정한다. s1~s6 계획은 조건부 후보이며 사전 예약 큐가 아니다.
- 같은 단계의 기술 재시도는 디스패처/워커의 복구 대상이다. 기술 실패를 새 과학 단계로 세거나 이름만 바꿔 재등록하지 않는다.
- REPLAY·REPLICATE도 같은 대상·base·계약이 대기/실행 중이면 중복 추가하지 않는다.
- 모든 필요한 질문이 기존 큐에 있거나, 근거 보강 후에도 게이트를 통과하는 독립 후보가 없으면 **신규 0건**을 허용한다. 기존 담당 ID, 미충족 질문, 재개 조건을 보고한다. 불확실성 표기만으로 계약·데이터·중복 게이트를 면제하지 않는다.

## 6. 안전하게 추가하고 결과를 다음 실행에 연결한다

- 쓰기 직전 두 탭의 상태를 다시 읽고 ID 및 위 중복 기준을 재검사한다. 같은 스냅샷으로 실행 중인 하네스의 중복 가능성을 명시한다. append 자체는 중복 잠금이 아니다.
- `values.append`의 `INSERT_ROWS`를 우선 사용한다. 없으면 시트 끝에 셀을 추가하는 원자적 `batchUpdate.appendCells`를 사용한다. 임의 행 번호에 `values.update`하거나 기존 행을 덮어쓰는 방식은 쓰지 않는다.
- 응답이 불확실하거나 timeout이면 다시 읽어 내 ID와 사양이 들어갔는지 확인한 뒤 재시도한다. 이미 있으면 재전송하지 않는다. 두 append 방식 모두 없으면 준비한 사양과 쓰기 불가 사유를 보고한다.
- 쓰기 전후 기존 행의 ID·내용·상대 순서, 새 행의 ID·사양·시각·빈 순서 칸을 확인한다. 동시 추가 행은 보존한다. 충돌·누락·중복이 보이면 추가 쓰기를 멈추고 실제 상태를 보고한다. 오래된 스냅샷으로 기존 행을 자동 복원하지 않는다.
- 다음 실행은 이전 행의 `[판단 요약]`과 `[가설 판정]`을 읽고 예상 관측과 실제 관측을 대조한다. 성능·가설 판정·실행 상태를 별도로 기록하고 그 결과로 다음 후보를 갱신한다.
