# PIVOT 모드 (현재 연구 basin이 포화됐거나 중요한 미해결 가설을 INCREMENT로 판별하기 어려울 때, 실행당 최대 1건)

PIVOT은 챔피언 레시피의 정보 표현, 예측 대상, 문제 정의 자체를 바꾼다. 결과는 INCREMENT와 같은 계약으로 판정한다. 2025 평가창 전체 3-seed이고, 대조는 챔피언이다.

## 피봇으로 인정하지 않는 것 (기존 축의 변형)
- LightGBM/ExtraTrees 하이퍼파라미터(트리 수, 학습률, objective 계수) 변경
- 기존 특징의 단순 selection·pruning·weighting
- 기존 사후보정(hourbias·jes affine·fusion)의 계수·bin·축소 상수 변경
- 앙상블 멤버·가중·seed 평균 변경
- 같은 정보를 다른 트리·신경망으로 다시 학습하는 것(PIVOT 범위 한정 — 아키텍처 전체를 바꾸는 것은 아래 ARCH로 낸다)
- 실패 실험의 임계값만 바꾼 재시도
- 챔피언 레시피의 휴리스틱 값(train_from, round, patch 폭, bias 표, 가중 표, 군집 수)을 바꾸는 것. 이것은 피봇도 INCREMENT도 아니고 금지다(`heuristics.md`). 학습형으로 바꾸는 것만 허용한다.

## 피봇 층 (후보는 서로 다른 층에서 고른다)
- **정보 표현**: 사이트별 시각 단위 표 대신 발행분 NWP 전체 시퀀스(round 10·17, WA·WB 전 변수, 주변 시간)를 학습형 인코더로 직접 넣는다. 사람이 정한 patch 폭·변수 부분집합 없이.
- **예측 대상**: 발전량 대신 물리 정규화 대상(청명 지수·용량 정규화 출력·청천 대비 비율)이나 분위수·분포를 예측하고, 표준 물리 모델로 발전량에 환원한다.
- **정산 정렬 학습**: 사이트 L1 대신 그룹 합 정산 손실(SMP 기후값·k 가중 L1, 실현 SMP는 쓰지 않음)을 직접 최소화하거나, 사이트 예측을 그룹 합 제약으로 reconciliation한다.
- **문제 분해**: 맑음/구름/강수·적설 regime이나 가동/정지 상태를 서로 다른 생성 메커니즘으로 보고 따로 모델링한다. 분류는 발행 시각 입력만으로 학습한다.
- **물리 구조**: 태양 기하 → 청천 일사 → NWP 기반 투과 → PV 성능 모델(셀 온도·clipping)을 명시적으로 두고 그 위에서 잔여만 학습한다(physics-informed hybrid).
- **새 정보 축**: 대회 원자료에서 아직 안 쓴 표현(예: observed 기상으로 학습한 NWP 오차 구조를 발행 시각 입력으로 옮기는 것), 또는 사용자 예외 범위의 위성 자료.
- **학습 단위**: 사이트×시각 독립 회귀 대신 발행일 단위 24시간 궤적, 사이트 집합(그룹) 단위로 학습한다.

## 구조 전환 후보 예 (매 실행 2단계 병목과 연결해 다시 고른다)
1. **정산 손실 직접 학습**: 현재 레시피는 사이트 L1로 학습하고 그룹 합·가중은 사후에 붙인다. 그룹 합 e_{g,t}에 SMP 기후값·k 가중을 건 손실로 학습하면 사이트 간 상쇄를 모델이 쓸 수 있다. 경쟁 설명: "W 질량은 사이트 개별 오차의 합이다" vs "그룹 단위 공통 오차(기상 공통 성분)다".
2. **청명 지수 대상**: y = P_cap · f(κ, T_cell) 형태로 대상을 바꾸면 계절·태양 고도 효과가 물리 모델로 빠지고 모델은 투과(구름)만 배운다. 경쟁 설명: "월별 이질성은 계절 기하 때문" vs "월별 기상 regime 때문".
3. **발행분 NWP 시퀀스 인코더**: patch 대신 발행분 전체를 학습형으로 넣는다. 경쟁 설명: "주변 시간 정보가 운량 위상 오차를 보정한다" vs "정보는 이미 시각 단위 값에 다 있다".

각 PIVOT은 반드시 다음을 적는다.
- 현재 구분되지 않는 두 개 이상의 연구가설.
- 이 구조가 두 가설을 어떻게 구분하는지.
- 성공 시 다음 연구 행동.
- 실패 시 닫히거나 우선순위가 낮아지는 축.
- 관련 물리·정산 메커니즘.
- 그 메커니즘을 표현하는 수학적 상태/추정량.
오라클 headroom은 해결할 가치가 큰 성분을 식별하는 데만 쓰고, 임의 회수율을 곱해 개선률을 만들지 않는다.

## 아키텍처 피봇 (ARCH 계보)
챔피언 계열(사이트별 LightGBM/ExtraTrees + 그룹 합 + 사후보정) 자체를 버리고 다른 구조로 예측한다. 한 행으로 판정하지 않고 계보(최대 6단계)로 키운다(`diagnostics.md` 계보 규칙, `row-template.md` ARCH 양식). 단독 판정만 하며 챔피언 계열과 블렌딩하지 않는다.

후보 계열 예시(각각 오늘의 병목과 연결해 쓴다):
- **물리 PV 성능 모델 + 학습 투과**: 표준 청천·셀 온도 모델로 사이트별 상한을 만들고, NWP 시퀀스로 투과율 분포를 학습해 그룹 합으로 집계. 과거 "solar-geometry proxy" smoke(X0309 −1.59%)는 특징 2개를 더한 것이라 구조가 다르다.
- **그룹 합 직접 + 사이트 분해 공동 학습**: 그룹 합과 사이트 출력을 동시에 예측하고 합 제약으로 묶는 계층 모델. 과거 Conv1d 직접 그룹(X0312)·top-down 배분(X0256)은 단발 smoke였다.
- **발행분 NWP seq2seq**: 발행분 WA·WB 전체 시퀀스 → 다음날 24시간 사이트 출력 궤적 동시 출력. 과거 attention 계열(A2)은 짧은 학습·단발 smoke였으므로 계보 예산으로는 미검증이다.
- **확률적 상태공간**: 사이트 가동 상태·구름 regime을 잠재 상태로 두고 발행 시각까지의 실적(rolling 정책 comparator)이나 NWP로 필터링.

## PIVOT 행 작성 규칙
- `[단일 변경]` 대신 "무엇을 버리고 무엇을 새로 보는지"를 쓴다. 그 밖의 부분은 챔피언 레시피를 그대로 쓴다고 명시한다.
- **정보 존재 여부 점검을 실험 안에 포함한다.** 예: 청명 지수 피봇이면 컷오프 이전 기간에서 κ̂의 MAE와 발전량 MAE의 관계를 먼저 보고한다. 이 점검은 진단 보고용이다. 결과가 나빠도 전체 평가창 3-seed까지 진행한다. "점검이 나쁘면 중단" 같은 게이트는 쓰지 않는다.
- 성공하면 W의 어느 성분(그룹·월·피크·흐린 날)에 영향을 줄 것으로 예상하는지 방향을 적는다.
- 실패하면 닫히는 연구 축을 명시한다.
- 외부 논문의 개선률을 우리 W 기대치로 옮기지 않는다.
